What the check does

eth_getTransactionReceipt(hash)   over 4 public Base RPCs, first one that answers
  status === "0x1"                the tx did not revert
  logs[] where address = USDC     native USDC on Base, not a bridged copy
  topics[0] = Transfer(...)       a real ERC-20 transfer event
  topics[2] = seller address      paid to the right wallet
  sum(data) >= 19e6               at least the asking price, in USDC units

Every rejection prints the reason in plain language. A hash from an exchange withdrawal has no USDC transfer to the seller and is refused.

The verifier in assets/verify.js is the same file the Node test suite loads, so the code that unlocks this page is the code under test: node tests/verify.test.js → 18 checks against a real Base mainnet transaction.
